# Dashboard Overrides

> **PROJECT:** CodeCompass
> **Page Type:** Application (signed-in)
> **Hand-authored** — not generated by the design-system tool.

> ⚠️ Rules here **override** `MASTER.md`. The true-black surface ramp and the
> black-on-green accent button from `pages/landing.md` apply here too.

---

## This is not a marketing page

MASTER.md's page pattern ("Minimal Single Column", "large typography", "lots of
whitespace") describes the landing page. The dashboard is the opposite job:
someone signed in is here to do something, not to be persuaded.

| | Landing | Dashboard |
|---|---|---|
| Density dial | 4 (standard) | effectively 6 — tighter |
| Headline size | `text-4xl`–`text-6xl` | `text-2xl` |
| Container | `max-w-6xl`, centred sections | `max-w-4xl` inside a fixed shell |
| Motion | scroll reveals, blurs | none beyond spinners and a chevron |

**No decorative accent blurs on this page.** The green wash belongs to the
hero. Here, accent green means *state* — ready, running — and diluting it with
decoration makes the states harder to read.

## Layout

`AppShell` (`components/layout/AppShell.tsx`) wraps every signed-in route:

- **`lg` and up:** `grid-cols-[15rem_1fr]`, sidebar `sticky top-0 h-svh` on
  `bg-surface` with a `border-r`.
- **Below `lg`:** sidebar becomes a top bar with a disclosure panel. Not a
  drawer — a drawer needs focus trapping and an overlay, and this navigation is
  four items long.

Unbuilt sections (Tours, Graph, Ask) render as `aria-disabled` spans with a
`SOON` marker, **not** as links. A nav item that navigates to a 501 is worse
than one that visibly is not ready yet.

**Account block.** The bottom of the sidebar shows the user's name and email
(both `truncate`d — emails are long) above a **Sign out** button. Below `lg` the
same block sits at the end of the disclosure panel; without that there would be
no way to sign out on a phone. Sign-out only takes effect once the server
confirms it — if the request fails, the button says so instead of pretending.

The whole shell renders only under `RequireAuth`. Signed-out visitors are sent
to `/login` and come back to the page they asked for after signing in.

## Status must not rely on colour

Every `RepositoryStatus` renders as icon + word + border colour together
(`StatusBadge.tsx`). Never reduce it to a coloured dot — WCAG 1.4.1, and it
also survives a greyscale printout in the report.

| Status | Icon | Colour |
|---|---|---|
| Queued | `Clock` | `line-strong` / `ink-muted` |
| Analysing | `Loader2` (spinning) | `accent` |
| Ready | `CheckCircle2` | `accent` |
| Failed | `AlertCircle` | `danger` |

The analysing spinner is the one animation on the page. It is inside the
`prefers-reduced-motion` block in `index.css` like everything else.

## Polling, not websockets

The repository list sets `refetchInterval: 3000` **only while something is
queued or analysing**, and returns `false` otherwise — an idle dashboard makes
no requests. Job detail polls at 2s and only for an expanded row. If the
backend grows a websocket later, this is the code to delete.

## Loading and empty states are part of the design

- **Loading:** skeletons at the real row height (`h-[5.5rem]`), so the layout
  does not jump when data lands.
- **Empty:** dashed border, not a solid card — it reads as a slot to fill.
- **Error:** `ErrorState` distinguishes a 501 from a real failure. A 501 gets
  "Not built yet" and **no retry button**, because retrying cannot help.

## Honesty notice

The page carries a standing notice that the queue is live but the analysis is
not. Every submitted job currently fails at the `ingest` stage, and expanding
the row shows the worker's real error message. **Remove that notice when M1–M7
land** — and do not replace it with a fake success state in the meantime.
