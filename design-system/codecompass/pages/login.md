# Login / Sign-up Page Overrides

> **PROJECT:** CodeCompass
> **Page Type:** Authentication
> **Hand-authored** — not generated by the design-system tool.

> ⚠️ Rules here **override** `MASTER.md`. Everything not listed follows the
> Master file *as amended by* `pages/landing.md` — the true-black surface ramp
> and the black-on-green accent button apply here too, and are documented there
> rather than repeated.

## Route shape

`/login` and `/signup` render the **same** page component
(`pages/LoginPage.tsx`) with a `mode` prop. They differ only in copy and in the
name field. Do not fork them into two files — they drift.

| Route | Mode | Extra field |
|---|---|---|
| `/login` | `signin` | — |
| `/signup` | `signup` | Name |

## Layout override

Not the Master's "Minimal Single Column". A **two-column split** at `lg` and up:

- **Left (form).** Max width `24rem`, vertically centred, own header with the
  wordmark and a Back link. No `SiteHeader` — a sticky marketing nav with
  "Sign in" buttons on the sign-in page is noise.
- **Right (`AuthAside`).** `bg-surface`, `border-l`, decorative accent blur, the
  value proposition and the same illustrative tour motif as the hero.

Below `lg` the aside is **hidden entirely**, not stacked. Nothing in it is
needed to complete the form, and pushing it under the fold on a phone just
makes the page longer.

## Method order

GitHub sits **above** the divider and email below it. This is a deliberate
break from the landing page's "both at equal weight" — by the time someone is
on this screen the repositories they want analysed are already on GitHub, so it
is the likely path. The landing page keeps them equal because it is still
making the pitch.

## Form rules

- **Labels are always visible.** Placeholder-only labelling is forbidden — the
  label vanishes exactly when it is needed. `components/ui/Input.tsx` enforces
  this by taking `label` as a required prop.
- **Errors render next to their field**, never as a summary block at the top,
  and set `aria-invalid` plus `aria-describedby`.
- **Validate on submit first.** Fields re-validate on every keystroke only
  *after* a failed submit, so nobody is corrected mid-word.
- **On a failed submit, focus moves to the first invalid field.**
- `noValidate` on the `<form>` — the browser's native bubbles are unstyled,
  untranslatable, and disappear on blur.
- Error text uses `text-danger` (`#EF4444`), measured 5.58:1 on `#000` and
  4.72:1 on `#181818`.

## Known placeholder

There is **no authentication backend yet** (module M8). Both the GitHub button
and a valid form submit call `navigate('/dashboard')` so the flow is walkable.
The real OAuth redirect and the real credential POST replace those two calls —
they are marked with comments in `features/auth/components/AuthForm.tsx`.
`/dashboard` is itself a placeholder page.

`/login`'s "Forgot password?" link currently points back at `/login`. It needs a
real route once password reset exists.
